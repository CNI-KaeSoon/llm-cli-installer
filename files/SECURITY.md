# 보안 정책

## 지원 범위

- 보안 수정은 최신 릴리스(현재 v3.0.0)에만 제공합니다.
- 이 저장소의 설치기는 **Windows 11 x64 실기기 E2E 검증을 거치지 않았습니다(NOT_RUN)**. 자동화 검증은 macOS의 PowerShell 7과 mock 기반입니다.

## 취약점 신고

- 공개 이슈에 취약점 세부 내용을 올리지 마세요.
- GitHub 저장소의 **Security → Report a vulnerability**(비공개 보고)로 신고해 주세요.
- 재현 절차, 영향, 사용한 릴리스 버전과 ZIP SHA256을 함께 보내 주세요. 토큰·비밀번호·개인 경로는 지우고 보내 주세요.

## 신뢰 경계와 알려진 잔여 위험

1. **공급자 설치 스크립트**: Codex·Claude Code·Antigravity는 공급자가 공식 URL에서 제공하는 PowerShell 설치 스크립트를 내려받아 별도 프로세스로 실행합니다. 이 스크립트는 공급자가 수시로 바꾸고 서명도 되어 있지 않아 버전·digest를 고정할 수 없습니다. 설치기가 하는 일은 다음뿐입니다.
   - HTTPS만 허용합니다.
   - redirect의 모든 hop이 구성요소별 허용 host인지 확인합니다(최대 3회).
   - 크기 상한(1 MiB)을 두고 HTML 응답을 거부합니다.
   - 본문이 올바른 UTF-8이 아니거나 NUL 문자가 있으면 실행하지 않습니다.
   - 실행 직전에 최종 host, 받은 bytes의 크기와 SHA256(`downloadSha256`), 디스크에 기록해 실제로 실행하는 bytes(UTF-8 BOM 포함)의 크기와 SHA256(`executedSha256`)을 로그에 먼저 남깁니다. 임시 파일은 사용자 `%TEMP%`에 쓰므로, 같은 사용자 권한의 다른 프로세스가 실행 직전에 파일을 바꾸는 경우까지는 막지 못합니다.

   공급자 계정이나 배포 경로가 변조되면 설치기도 막을 수 없습니다.
2. **npm 패키지(Grok, Legacy Gemini)**: 공식 registry(`https://registry.npmjs.org/`)를 명령줄로 강제합니다. 패키지 무결성은 npm이 registry 메타데이터로 검증합니다. 버전은 고정하지 않고 설치 시점의 최신 안정판을 받으며, 패키지의 install script가 사용자 권한으로 실행됩니다.
3. **실행 파일 해석**: Windows PowerShell은 `%SystemRoot%` 아래 절대경로로 실행합니다. `winget`, `npm`, `pymanager`, 설치된 CLI는 PATH에서 이름으로 찾습니다. PATH 앞쪽에 악성 실행 파일이 있으면 그 파일이 실행될 수 있습니다. **관리자 권한 PowerShell이 아닌 일반 사용자 PowerShell에서 실행하세요.**
4. **cmd.exe 인자**: npm처럼 `.cmd`로 실행되는 도구에는 cmd 메타문자(`" % ! ^ & | < >`)나 제어문자가 든 인자를 넘기지 않고 실행을 거부합니다. 완전한 cmd quoting 검증은 Windows E2E 항목으로 남아 있습니다.
5. **시간 제한**: 제한 시간이 지나면 설치기가 직접 시작한 프로세스만 종료합니다. 그 프로세스가 만든 하위 프로세스는 남을 수 있습니다(process tree 종료는 미구현).
6. **권한 상승 채널**: UAC helper는 이번 릴리스에서 비활성화되어 있습니다. 관리자 권한이 필요한 설치는 WinGet과 공급자 설치기가 요청하는 UAC 창을 따릅니다.
7. **기존 설치 이전(migration)**: 기본적으로 비활성화되어 있습니다(release gate). gate를 열기 전에는 복구 판정 강화, 복구 불가 journal 정리 절차, PATH snapshot 정리가 필요합니다.
8. **서명 인증서 판정**: 공급자별 서명 조직명 목록은 Windows 실기기에서 확인하지 않았습니다. 판정이 틀리면 기존 설치의 출처 등급이 낮게 표시될 뿐이며 제거 동작에는 영향이 없습니다.

## 릴리스 무결성

- 릴리스 ZIP과 같은 이름의 `.sha256` 파일을 함께 게시합니다. 코드 서명과 attestation은 아직 제공하지 않습니다.
- ZIP 안의 `manifest.sha256`은 압축 해제 후 파일 누락·변조를 검출하는 용도입니다. ZIP 자체의 진위는 증명하지 못하므로 README 절차로 ZIP의 SHA256을 먼저 확인하세요.
